OpenVaultDB (OVDB) — открытый протокол и платформа для баз данных приложений, принадлежащих пользователю. Приложения подключаются к вашему хранилищу и хранят данные в пространствах имён, которыми сами управляют, — но само хранилище и всё, что в нём лежит, принадлежит вам.

Установка OpenVaultDB

Попросите агента — или выполните одну команду.

Прямые установщики скачивают подходящий официальный релиз, проверяют его контрольную сумму SHA-256 и не требуют Go.

Все варианты установки (на английском)

Install and set up OpenVaultDB on this machine.

Follow the official instructions:
https://openvaultdb.com/agent-instructions/install
macOS или LinuxТерминал
(p=$(mktemp) && trap 'rm -f "$p"' EXIT && curl -fsSL https://openvaultdb.com/install.sh -o "$p" && sh "$p")
WindowsPowerShell
$p=Join-Path $env:TEMP ("ovdb-"+[guid]::NewGuid()+".ps1"); try { irm https://openvaultdb.com/install.ps1 -OutFile $p -EA Stop; & $p } finally { Remove-Item $p -EA SilentlyContinue }

Эти команды доверяют установщику, который отдаёт openvaultdb.com. Исходник для shell · Исходник для PowerShell. Каждый установщик проверяет контрольную сумму скачанного релиза перед установкой. Если вам важна поставка через менеджер пакетов, выбирайте Homebrew через пошаговую установку (на английском).

Настроить приложение
Главный принцип
Приложения не владеют данными пользователей. Пользователи владеют своими данными и разрешают приложениям доступ к ним.

Вы решаете, где живёт хранилище: на ноутбуке, домашнем сервере, VPS, в инфраструктуре OpenVaultDB или в вашем собственном облачном аккаунте. Каждое приложение получает изолированное пространство имён, которым полностью управляет: создаёт собственную схему, отвечает за свои миграции и распоряжается жизненным циклом своих данных. Никакой глобальной модели данных. Никакой привязки к поставщику.

Что даёт протокол

Владение, переносимость и полный журнал изменений — по замыслу.

Данные принадлежат пользователю

Экземпляр OpenVaultDB принадлежит вам. Приложения получают токены и права доступа с ограниченной областью действия, которые можно отозвать, — но никогда не владение вашими данными.

Пространства имён приложений

Каждое приложение получает изолированную область, где создаёт, изменяет и удаляет собственную схему и данные. Миграции и версионирование — на стороне приложения.

Своё хранилище данных

Разверните у себя, возьмите управляемый тариф или подключите собственные Firestore, Postgres, SQLite или облачную БД через адаптеры хранилищ DALgo.

История на основе Git

Эталонный движок inGitDB версионирует каждое изменение: история коммитов, журнал аудита и возможность откатить запись, таблицу или всё хранилище целиком.

Ограниченный, отзываемый доступ

Доступ строится на токенах и правах доступа с ограниченной областью действия, которые можно отозвать в любой момент. Ваши данные остаются в выбранном вами хранилище; в MVP данные хранилища не шифруются, поэтому выбирайте хост, которому доверяете.

Переносимый API запросов

TugQL открывает только те возможности, что переносимы между всеми бэкендами, — поэтому запросы, работающие на Git, работают и на Postgres, SQLite или Firestore.

Сервер не нужен

Ваш браузер пишет прямо в ваш Git-репозиторий.

В базовом бессерверном режиме и в режиме самостоятельного размещения приложение читает и записывает ваши данные прямо из браузера в Git-репозиторий, которым вы владеете, — с аутентификацией через собственный вход приложения через GitHub или через fine-grained токен, который вы выдаёте. OpenVaultDB вообще не участвует в основном пути данных. Для необязательного управляемого резервного копирования и экспорта OpenVaultDB отдельный сервис владеет собственным GitHub App. inGitDB и INGR.io сохраняют каждое изменение как чистый коммит, который можно слить.

  • Базовые и самостоятельно размещаемые приложения работают с GitHub напрямую; управляемый экспорт — необязательный отдельный сервис
  • Приватные репозитории — для приватных данных, публичные — для публичных
  • Ваши данные живут в репозитории под вашим контролем — клонируйте его куда угодно

Лучше всего подходит для личного использования и редко меняющихся данных. Нужна пропускная способность записи или масштаб? Запустите inGitDB на сервере или используйте облачную базу данных или РСУБД через DALgo — выбирайте инструмент под задачу.

Как всё складывается

Один протокол — много бэкендов.

OpenVaultDB определяет протокол и API. Запросы проходят через TugQL в DALgo — слой абстракции данных, — который отображает их на выбранный вами адаптер хранилища. Эталонный путь записывает Git-дружественные файлы INGR.io в Git-репозиторий.

Экосистема

Небольшое семейство сфокусированных, совместимых частей.

DataTug

DataTug ↗

DataTug помогает разработчикам изучать схемы баз данных, писать и выполнять запросы и разбираться в их результатах. DataTug работает с OpenVaultDB. Как создавались инструменты разработки DataTug (на английском).

TugQL

Язык запросов ↗

Основной API. Переносимый язык запросов и изменений, построенный на возможностях DALgo, — намеренно не полноценный SQL.

DALgo

Слой абстракции данных ↗

Отображает переносимые запросы на провайдеры бэкендов, так что одна модель запросов охватывает множество баз данных.

inGitDB

Движок на основе Git ↗

Эталонный движок хранения. Проверяемая история, простой откат и версионируемые данные поверх Git.

INGR.io

Формат хранения ↗

Git-дружественный структурированный формат, рассчитанный на чистые диффы, слияния и разрешение конфликтов.

Хранилище

Определено открыто

Спецификация, а не импровизация.

Протокол OpenVaultDB и его эталонная реализация описаны как открытые машиночитаемые спецификации по стандарту SpecScore.md. Спецификация — источник истины, поэтому любой разработчик, любой инструмент и любой ИИ-агент может прочитать её и построить совместимую реализацию.
