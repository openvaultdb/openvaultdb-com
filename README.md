## About OpenVaultDB

OpenVaultDB is an open platform for user-owned application databases. It enables applications to store and access data in user-controlled storage through standard APIs, portable storage backends, and open specifications.

Learn more at https://openvaultdb.com

## Hosting and deployment

The public website is configured as the `openvaultdb-com` Cloudflare Workers
Static Assets Worker with no Worker script. [`wrangler.jsonc`](wrangler.jsonc)
serves `public/` as static assets, keeps clean URLs without trailing slashes, and
declares `openvaultdb.com` as its custom domain. [`public/_headers`](public/_headers)
sets the site's security and cache headers.

Firebase Authentication and Firestore remain browser dependencies. The
Firebase GitHub workflow deploys Firestore rules only; it no longer publishes
Firebase Hosting. The `hosting` block in `firebase.json` exists solely for the
local Playwright Firebase emulator.

The canonical AI installation instructions live in
`content/agent-instructions`; the canonical standalone skill lives in
`content/agent-skills`. Generate the cold-static `/install`,
`/agent-instructions/*`, homepage prompt, public skill, and verified skill
installer before publishing:

```sh
npm ci
npm run check
```

The `Build and deploy website` GitHub Actions workflow generates and verifies
one release artifact on pull requests, main pushes, and manual dispatches.
Artifacts remain available while automatic publication is disabled. Once scoped
credentials are configured and `CLOUDFLARE_DEPLOY_ENABLED` is `true`, main pushes
or manual runs on main deploy the same artifact with Wrangler, without
rebuilding. See [DEPLOY.md](DEPLOY.md) for activation and artifact publication.

Release order matters: first publish an `ovdb` release whose normal help
contains the documented onboarding commands, then publish the generated web
pages. The install instructions verify that command surface and stop on an
older release.

Maintainers can run the versioned Luna clean-room procedure in
[docs/ai-installation-acceptance.md](docs/ai-installation-acceptance.md).

## Languages

The site is published in English (`/`) and Russian (`/ru`). The pages are
hand-written HTML, one file per locale, so each string lives in exactly one
place per language:

| English | Russian |
| --- | --- |
| `public/index.html` | `public/ru/index.html` |
| `public/privacy/index.html` | `public/ru/privacy/index.html` |

The install block of each homepage is generated by `npm run build` from
`scripts/build-agent-instructions.mjs`, which holds its English and Russian
wording side by side (commands and the agent prompt are identical). Interface
strings in `public/js/analytics.js` (consent banner) and `public/js/auth-ui.js`
(sign-in dialog) pick their language from `<html lang>`. `/ru` keeps the site's
no-trailing-slash convention (`/ru/` redirects to `/ru`). Both pages carry a
language switch, reciprocal `hreflang` (`en`, `ru`, `x-default` = English),
per-locale Open Graph (`og.png`, `og-ru.png`) and sitemap alternates (the
sitemap source is `content/discovery/sitemap.xml`). Only the home and privacy
pages are translated; install, docs and the signed-in area stay English and are
labelled so on the Russian pages. To add a locale, copy `public/ru/`, add its
copy to the build script and extend `test/locale.test.mjs`.

## Film slot

The homepage has a hidden film section. It is switched on in one place,
[`public/js/video-config.js`](public/js/video-config.js):

```js
window.OVDB_VIDEO = {
  enabled: false,                       // 1. set to true last
  locales: {
    en: { id: "", poster: "/video/poster-en.svg", width: 1280, height: 720 },
    ru: { id: "", poster: "/video/poster-ru.svg", width: 1280, height: 720 },
  },
};
```

1. Put the 11-character YouTube video id of the English and Russian film in
   `locales.en.id` and `locales.ru.id`. A locale without an id keeps the slot
   hidden on that page.
2. Replace `public/video/poster-en.svg` and `poster-ru.svg` (placeholders) with
   the real posters, or point `poster` at another local image and set its real
   `width` and `height` so the page does not shift when it appears.
3. Set `enabled` to `true`.

Nothing is requested from YouTube until a visitor clicks the poster; the player
then loads from `youtube-nocookie.com`. `e2e-analytics/locale.spec.ts` covers
this. Localized slot headings live next to the slot in each HTML file
(`data-play-label`, `data-iframe-title`, heading).

## Tests

`npm test` runs the Node tests (including `test/locale.test.mjs`);
`npm run e2e:analytics` runs the self-contained Playwright specs
(`consent.spec.ts`, `locale.spec.ts`) against `public/` with no network.
